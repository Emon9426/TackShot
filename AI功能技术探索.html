1调研背景：需求、项目约束与调研方法

  • 引入 “GitHub Copilot SDK”，用 GitHub Copilot 账户接入 AI 模型（不另购 OpenAI/Azure key）；
  • 核心场景一：OCR——读取截图中的文字；
  • 核心场景二：读图之外其他可能 worthwhile 的 AI 功能（本报告第 5 章给出建议清单）；

1.2 必须同时满足的项目硬约束

约束来源对 AI 方案的直接影响

3四条候选技术路线详析与对比矩阵

路线 A官方 GitHub Copilot SDK（Java 版）官方重

是什么：GitHub 官方多语言 SDK（仓库 github/copilot-sdk），Java 坐标 com.github:copilot-sdk-java（Maven/Gradle），公测于 2026-04-02，GA 于 2026-06。提供与 Copilot CLI / 云端 Agent 同源的 agent runtime：多轮会话、流式输出、自定义工具回调、二进制附件（图片/截图）内联发送、系统提示词定制。

关键架构事实（决定性）：SDK 并不直接调用公网 REST——它在本地拉起 Copilot CLI 进程，通过 RPC（session.create / session.send / session.resume）与之通信；CLI 负责实际的模型调用与凭据管理。官方 getting-started 明言各语言 SDK 会“自动捆绑 CLI”。

认证：三种方式——① 默认：复用本机 copilot CLI 的登录态（GitHub OAuth 设备流，凭据入系统 keychain）；② OAuth GitHub App：用户授权你的应用，把用户令牌（gho_/ghu_，也接受细粒度 PAT github_pat_）传入 SDK，应用即可代用户发起 Copilot API 请求（要求用户持有 Copilot 订阅）；③ BYOK：自带 OpenAI/Anthropic key 则无需订阅（但那就不是“Copilot 账户”了）。

对本项目的障碍（按严重度）：

  • Java 17+——本项目 --release 11、公司机 JDK 11/17，引入即被迫要求所有用户升 17+；
  • CLI 子进程——首次运行要下载/捆绑 Copilot CLI（原生二进制 + Node 生态，数十 MB 级），常驻时额外内存开销与 128MB 预算冲突，公司环境“便携免装”不满足；
  • SDK 面向“编码 Agent”场景（工具调用、文件操作），对“截图→文字”这种单轮视觉调用属于杀鸡用牛刀。

结论：暂不采用。当未来项目升级到 Java 17/21 运行时、且公司环境允许分发 CLI 时，可作为正式化迁移目标（见 4.8 节）。

路线 B直连 api.githubcopilot.com（OpenAI 兼容开放端点）轻量非官方文档

是什么：Copilot 后端暴露的 OpenAI 兼容推理端点，基础地址 https://api.githubcopilot.com，提供 /models（列出订阅可用模型）、/chat/completions（经典 OpenAI 格式）、/responses（新版 Responses API；gpt-5 系列与 Codex 变体仅走此端点）。

产业采用度（重要佐证）：Docker 官方 AI Agent 文档将其列为正式 Provider（含认证细节与必带请求头）；aider 将其列为官方支持的模型来源之一，并声明“按 Copilot 文档规则使用、无网页抓取”；LiteLLM 内置 github_copilot/ Provider（OAuth 设备流 + 自动令牌管理）。它同时是 GitHub 官方托管 MCP 服务器的域名（api.githubcopilot.com/mcp/）。

认证（两种，Docker 文档均有记载）：

  • PAT 模式（推荐首选）：用户在 GitHub 设置中生成带 copilot scope 的 PAT，粘贴进 TackShot 设置——无 OAuth 应用注册、无浏览器回调，实现与 UX 最简单；要求有效 Copilot 订阅（Individual/Business/Enterprise）。
  • OAuth 设备流模式（RFC 8628，增强项）：github.com/login/device/code → 用户浏览器激活 → 轮询 github.com/login/oauth/access_token → 持久化 refresh；社区资料（LiteLLM、copilot-api、picoclaw 等）证明可行。是否可用自注册 OAuth App 的 client_id（而非伪装 VS Code 官方 ID Iv1.b507a08c87ecfe98）需 PoC 验证——若可行则合规性显著更好。

必带请求头：Authorization: Bearer <token> 与 Copilot-Integration-Id（Docker 默认发 copilot-developer-cli，PAT/OAuth 令牌均接受；缺失会被 400 拒绝）。LiteLLM 还会注入 editor-version 等头。

视觉/OCR 能力：Docker 文档明确“复用 OpenAI 客户端，多模态输入可用（前提是模型支持）”。可用模型含 gpt-4o（多模态均衡）、gpt-4o-mini（快且省）、claude-sonnet-4、gemini-2.5-pro、o3-mini 等。图片按 OpenAI 格式以 image_url（data URI base64）传入——这正是 OCR 所需的完整能力闭环（中文识别效果需 PoC 实测，见第 7 章）。

实现代价（对本项目极友好）：Java 11 标准 java.net.http.HttpClient + 手写 JSON/SSE 解析即可，零新增依赖、无常驻子进程、按需短连接，内存可控。

主要风险：端点无公开官方文档与 SLA，字段/路径可能变（R1）；非官方客户端调用属条款灰色地带，GitHub 对滥用（高并发倒卖、共享账号）有封号先例，但 Docker/aider/LiteLLM 这类正常低频个人用例至今正常运行（R2）。两条都有缓解手段，见第 6 章。

结论：推荐为主路线。是唯一同时满足“Copilot 账户 + Java 11 + 零依赖 + 低内存”的方案。

路线 CGitHub Models（已退役）／ Azure AI Foundry（官方继任者）

GitHub Models：2026-07-30 全量退役（playground / 目录 / 推理 API / BYOK 全部关闭），判死，无讨论价值。互联网上大量“GitHub Models 免费用 GPT-4o”教程已全部失效。

Azure AI Foundry（官方推荐迁移目标）：模型目录更广、正式 SLA，但需要 Azure 订阅 + 部署 + API key，与“直接用 GitHub Copilot 账户”的诉求不符；且 Azure OpenAI 区域/配额在公司环境未必可用。作为备案记录，不推荐。

路线 D本地 OCR（Windows 内置 OCR ／ Tesseract）离线零成本

方案 D1：Windows 内置 OCR（推荐）。Windows 10/11 自带 Windows.Media.Ocr WinRT API，离线、免费、随系统语言包支持中英文。无需引入任何二进制——用系统自带 powershell.exe 加载 WinRT 类型即可调用（项目 build.sh 已有调用 PowerShell 的先例）。局限：纯文字行识别，不理解表格结构/公式/语义，复杂版面排版还原弱。

方案 D2：Tesseract（tess4j/JNA + traineddata）。识别质量与 D1 同级略优，但需携带原生库 + 语言数据约 30~60MB，与“轻量便携”冲突，不推荐，仅记录。

定位（关键设计决策）：本地 OCR 不与云端模型竞争，而是兜底与互补——① 未配置 Copilot / 网络不可用 / 额度耗尽时降级可用；② 隐私敏感截图走“本地模式”；③ 与 AI 结果对照校验（降低大模型“幻读”风险）。两者共用同一 AiProvider 抽象（见 4.2）。

4推荐技术方案：轻量直连 + 本地兜底 + 官方演进预留

推荐组合：路线 B 为主（云端视觉模型，覆盖 OCR/翻译/问答/表格/公式）+ 路线 D 为兜底（本地 OCR，覆盖离线/隐私/降级），并以 Provider 抽象层为路线 A 预留官方化迁移接口。所有云端调用消耗用户自己 Copilot 订阅的 AI Credits，项目方零 API 成本。

4.2 Provider 抽象（一个接口，三种实现）

// 预留接口示意（本轮不实施，仅表达设计）
interface AiProvider {
    String name();                          // "copilot" / "local-ocr"
    boolean ready();                        // 已配置令牌 / 系统语言包可用
    void chat(AiRequest req, AiListener cb) // req=图片+功能模板+参数；cb=流式/完成/失败;
}
record AiRequest(BufferedImage image, PromptTemplate tpl, Map<String,String> params) {}

功能层只面向 AiProvider 编程：OCR、翻译、问答不关心后端是谁；设置页可切换“云端 / 本地 / 自动（云端失败转本地）”。未来切官方 SDK（路线 A）时新增实现类即可，功能层零改动。

4.3 认证与令牌管理（安全重点）

项设计
首选认证PAT 模式：设置页粘贴仅含 copilot scope 的 GitHub PAT（最小权限原则），“测试连接”按钮实时验证（调 GET /models）。
增强认证（PoC 后决定）OAuth 设备流：用户点“登录 GitHub”→ 显示 8 位设备码 + 自动开浏览器 github.com/login/device → 轮询拿 access/refresh token。优先验证自注册 OAuth App 的 client_id 可用性（合规、可署名）；若端点校验强制官方 client_id，则降级只提供 PAT 模式，不做客户端伪装（降低 R2 风险）。
令牌存储不落 config.json 明文。用项目已有的 JNA 调 Windows 凭据管理器（CredWriteW/CredReadW，DPAPI 加密，按当前用户隔离），凭据名如 TackShot/CopilotToken。
请求头约定Authorization: Bearer <PAT> + Copilot-Integration-Id: copilot-developer-cli（Docker/aider 同款，PAT 与 OAuth 令牌均接受）。
失效处理401/403 → 气球提示“令牌失效，请到设置重新粘贴”；设置页提供“清除令牌”。

4.4 调用协议与模型选型

  • 能力探测：启动后首次使用时 GET /models 缓存可用模型列表（随订阅档位不同而不同），设置页下拉只列真实可用的。
  • 主端点：POST /chat/completions，OpenAI 消息格式；图片走 {type:"image_url", image_url:{url:"data:image/jpeg;base64,..."}}；stream:true 走 SSE 逐 token 渲染到结果浮窗。
  • 模型策略（默认自动分档，用户可改）：
档位模型（示例）用途备注
快速档（默认）gpt-4o-miniOCR 提取、翻译、文件名建议最省额度，速度最快
均衡档gpt-4o截图问答、报错诊断、表格/公式版面理解与中文更强
深度档claude-sonnet-4 / gemini-2.5-pro复杂文档还原、长图分析用户手选

注意：gpt-5 系列及 Codex 变体仅在 /responses 端点提供（走 /chat/completions 会 400）——首版不接 gpt-5 系，/responses 支持列为后续增强。模型 ID 与可用性以 /models 实测为准（PoC-1）。

4.5 图片预处理与内存预算（128MB 约束下）

  • 截图先长边缩至 ≤1568px（多模态模型最优分辨率，超过只增 token 不增效）、转 JPEG 质量 85（文字类截图典型 1080p → 150~400KB）；
  • base64 后约 0.2~0.55MB，叠加 Java String UTF-16 与 JSON 拼装缓冲，单次调用峰值 < 3MB——128MB 堆内完全安全；
  • 显式 Content-Length + 一次写出发送，避免流式上传缓冲放大；HttpClient 设置连接超时 10s / 请求超时 60s（流式期间按读空闲计算）。

4.6 成本估算（AI Credits，token 计费）

按 2026-06-01 起的用量计费规则（按各模型公开 API 价率折算 token）。估算：1080p 截图缩放后约 1,000~2,000 视觉输入 token + 提示词 ≈ 100 token，输出 300~800 token。gpt-4o-mini：单张约 $0.0003~0.001（Pro 档每月 $10 额度 ≈ 可支撑数千张）；gpt-4o：单张约 $0.005~0.02。结论：默认 mini 档下日常用量对订阅额度几乎无感。⚠ 以上为推算值，PoC 时以真实账单页核对。

4.7 UI/UX 集成设计（复用现有交互语言）

入口交互

4.8 隐私、合规与降级

  • 隐私明示：设置页与首次使用时提示“启用云端 AI 后，截图内容将发送至 GitHub 及其模型供应商（OpenAI/Anthropic/Google）处理”；提供“本地模式”开关（仅本地 OCR，绝不联网）。
  • 公司敏感信息：默认在发送前显示一次确认（可勾选“不再提示”）；敏感检测功能（P2）落地后可自动预警。
  • 降级链：云端失败（网络/429/额度尽/令牌失效）→ 提示并询问是否转本地 OCR；本地语言包缺失 → 提示安装路径。
  • 官方化演进：Provider 抽象使未来升级 Java 17 + 引入官方 Copilot SDK（路线 A）成为纯增量替换，UI 与功能层不动。

5建议的 AI 功能清单（P0/P1/P2）

均基于“截图/贴图在手上”这一 TackShot 独有上下文设计；所有功能共用同一套 Provider/结果浮窗基础设施，边际开发成本递减。

P0（首批，价值最高、实现最直接）

#功能说明输入 → 输出建议模型档

P1（第二批，差异化价值）

#功能说明建议模型档

#功能说明

ID风险等级影响缓解措施
