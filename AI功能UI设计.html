1设计原则（继承现有产品哲学）

  1. AI 是可选增强，不是依赖——默认关闭（opt-in）；未配置/离线/失败时所有既有功能不受任何影响；本地 OCR（FR-8.5，P1）落地后可完全离线。
  2. 不碰用户剪贴板——延续 V2.0.3 决策：识别结果只在用户点击「复制」按钮时才写剪贴板，绝不自动覆盖。
  3. 视觉与现有 UI 同族——结果浮窗/菜单复用 Tb.java 自绘色板（深色石板 + 蓝强调 + 雅黑探测字体），与贴图悬浮菜单、托盘菜单同一视觉语言；随 DPI 缩放。
  4. 过程可见、可打断——流式逐字渲染（用户即时看到产出）；加载中可取消（Esc）；错误必须给出下一步动作（重试 / 打开设置）。
  5. 隐私前置——首次使用强提示「截图将发送至 GitHub 及模型供应商」；「发送前确认」默认开启（可关闭）；令牌只存 Windows 凭据管理器。

3核心组件 · AI 结果浮窗（FR-8.4）

3.1 形态与定位（决策点 D1）

浮窗承载所有 AI 功能的产出，是本设计最重要的新组件。三个候选形态：

方案形态优点缺点
A. 停靠贴图旁（推荐）独立无装饰 JFrame，出现在贴图右侧（放不下时左侧/下方，屏幕夹紧）；继承该贴图的置顶层级；可拖动；宽 420 / 高自适应（上限 60% 屏高，超出滚动）图文同屏对照（截图与识别结果并排）；贴图关闭时浮窗随之关闭；一次心智模型贴图在屏幕边缘时需智能避让
B. 屏幕居中独立窗模态对话框居中实现最简单遮挡贴图本身，无对照价值；打断感强
C. 贴图内嵌展开贴图窗口自身向下扩展一块内容区视觉最一体贴图窗口结构复杂化（点击穿透/缩放/拖动都要特判）；与贴图“轻”的定位冲突

推荐 A：技术上是普通 Swing 窗口（复用无装饰 JFrame + makeActivatable 经验），交互上“贴图=源、浮窗=果”关系清晰。

3.6 状态机

未配置→ 加载/流式中→ 完成→ 换模型 / 重试↩ 加载/流式中
加载/流式中→ 错误（网络/401/429/额度）→ 重试 / 打开设置
  • 任何状态 Esc 关闭浮窗；进行中的请求后台可继续（重开贴图右键可见结果）或随浮窗关闭而取消（决策点 D5：默认取消，避免无主请求耗额度）；
  • 「发送前确认」开启时，加载前先弹一次性小气泡卡：「将把这张截图发送至 GitHub（gpt-4o-mini）— [发送] [取消 [☑不再询问]]」；
  • 贴图关闭 → 浮窗关闭；贴图编辑保存 → 结果过期提示（浅黄条“图片已修改，结果可能过期 — [重新识别]”）。
